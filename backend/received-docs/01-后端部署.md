# 后端接收与启动

这份说明对应“完整后端源码包”；前端业务字段仍由前端确定，传输形式见《前端交接说明》。当前交付包含实际 API、Multi-Agent、语音服务、数据、测试和调试页面，没有把密钥和本机历史会话打进去。

## 1. 包内有什么

| 路径 | 内容 |
|---|---|
| `server/` | 完整 API、WebSocket、调度器、餐厅人格、证据容错、攻击点记忆、STT/TTS、兼容旧 Demo/LiveKit 的代码 |
| `scripts/`、`tests/` | 启动、模型下载、检查与测试；本机管理脚本也保留 |
| `web/` | 调试控制台及旧演示页；这是可运行的参考界面，产品继续沿用前端现有实现 |
| `data/latest/` | 6 份当前商户 CSV；当前实时接口按这些 `shop_uuid` 读取 |
| `data/brand_characters.json` | 角色命名依据；人格系统提示词由代码构建 |
| `data/restaurants.json` | 旧 Demo 的基础数据，现有 app 导入仍会读取 |
| `voices/` | CosyVoice 使用的三份参考 WAV |
| `runtime/CosyVoice/` | 当前 CosyVoice 与 Matcha-TTS 的源码、许可证，不含模型和 Python 环境 |
| `config/` | 当前提示词快照、模型校验清单、组件版本记录 |
| `.env.example`、`requirements*.txt` | 空密钥配置模板及依赖 |
| `start_backend.cmd`、`scripts/run_backend.py` | 可迁移启动入口，使用接收方自己的 Python |

`MANIFEST.sha256.json` 记录包内文件和哈希。文档在另一个压缩包。

## 2. 先启动 API 和文字联调

以下以 Windows / 官方 Python 3.11 为例，进入解压后的 `eat-what-backend` 根目录。建议放到 F 盘等有足够空间的位置，缓存会建在项目的 runtime 中。

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-handoff.txt
Copy-Item .env.example .env.local
```

自行编辑 `.env.local`：填写授权的 `LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY`。本机使用过的模型名是 `deepseek-pro`，必须配合提供该模型的服务地址；不要只凭模型名猜接口。

```powershell
.\.venv\Scripts\python.exe scripts/run_backend.py --check
.\.venv\Scripts\python.exe scripts/run_backend.py
```

打开 `http://127.0.0.1:8771/console.html`。语音服务尚未启动时，先取消“接收并播放后端 TTS”，建立会话后点“只跑一轮”。未配置 LLM 时只会进入开发降级模式，不能用它评估真实 Agent 表达。

`start_backend.cmd` 是同一启动入口。原来的 `start_console.cmd` / `manage_console.py` 等保留了本机便携运行时路径，新机器优先使用上述入口。

若只想先装 API 依赖，可以先 `pip install -r requirements.txt`；麦克风 VAD/STT 和全部验证脚本需完整的 `requirements-handoff.txt`。`config/python311-installed.txt` 是本机环境版本快照，供排查差异，不代替不同平台的依赖解析。

## 3. 启动完整语音

当前实测路线是 Windows + NVIDIA GPU 的 CosyVoice 3；API/STT 使用 Python 3.11，TTS 单独使用 Python 3.10，不要混成一个环境。模型权重需要另行下载，占用约数 GB；接收方需准备可用的 CUDA/GPU 环境。

### TTS：独立终端

源码已带上，无需重新克隆。先用 API 环境下载模型，脚本会校验 SHA256：

```powershell
.\.venv\Scripts\python.exe scripts/download_cosyvoice.py
py -3.10 -m venv runtime/cosyvoice-env
.\runtime\cosyvoice-env\Scripts\python.exe -m pip install torch==2.3.1 torchaudio==2.3.1 --index-url https://download.pytorch.org/whl/cu121
.\runtime\cosyvoice-env\Scripts\python.exe -m pip install -r requirements-cosyvoice-win.txt
.\runtime\cosyvoice-env\Scripts\python.exe scripts/cosyvoice_service.py
```

模型落点：`runtime/CosyVoice/pretrained_models/Fun-CosyVoice3-0.5B`，仓库为 `FunAudioLLM/Fun-CosyVoice3-0.5B-2512`。`config/cosyvoice-model-manifest.json` 是交付时所用模型的校验记录，下载器的当前上游清单仍以实际下载结果为准。

`http://127.0.0.1:8772/health` 返回 ready 后，API 的 `.env.local` 使用：

```dotenv
TTS_PROVIDER=cosyvoice-http
COSYVOICE_URL=http://127.0.0.1:8772
WHISPER_MODEL=small
WHISPER_DEVICE=cpu
WHISPER_COMPUTE_TYPE=int8
```

然后在另一个终端启动 API。首次开麦会加载 Silero VAD 和 Whisper small，可能需要下载模型；缓存保存在项目 runtime。已具备兼容 NVIDIA 环境时可改 STT 为 `cuda / int8_float16`，CPU 配置更便于先排除原生依赖问题。浏览器开麦仍需用户授权。

CosyVoice 的 ONNX 提取部分使用 CPU、主推理使用 GPU；当前没有逐店精调真实地域口音。Linux/macOS 等其他环境未做本机同等验证。

## 4. 验证与对外联调

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe scripts/validate_attack_memory.py
.\.venv\Scripts\python.exe scripts/validate_evidence_continuity.py
```

单元测试不需要真实麦克风；后两个脚本会调用接收方配置的真实 LLM。故障现场回放脚本若依赖原机 artifacts，需要另备相应样本；原机聊天/日志未打包。真实语音、GPU 和浏览器权限在接收方完成配置后再测。

当前 WebSocket 路径是 `/api/realtime`；两边数据结构确定后在后端做业务字段适配。调度和餐厅均在后端，前端不保存模型密钥。

默认只监听本机。需要局域网联调时由部署负责人显式选择可达 host，例如 `scripts/run_backend.py --host 0.0.0.0`；再配置防火墙、HTTPS/WSS、反向代理和访问控制。当前 Demo 未提供生产鉴权，不应直接公开到公网。前端的 127.0.0.1 不代表后端同学的电脑。

当前 WebSocket 路线不要求启动 LiveKit 服务器；`deploy/` 和旧 LiveKit worker 作为另一条历史演示路线保留。数据库会在新环境首次启动时新建，当前没有旧 WebSocket 会话断线续传功能。

## 5. 明确未随包提供

API 密钥、`.env.local`、虚拟环境和便携 Python、模型权重、下载缓存、日志、会话数据库、本机录音和故障现场聊天。它们不是缺失的业务源码；运行依赖与模型按上文重新配置。
