# 智能体舞台

把 agent-studio 的两样能力并进这个前端，全部用 TypeScript 写在浏览器里：

1. **按店铺信息实时生成店主形象**：在滑卡、集合开场、拉幕登台这些动画里出现。
2. **用 Jev 决定每句台词的表演**：包括说话人的表情、手势、身体动作、视线，以及台上每位听众的反应。

移动端页面不放导演台。台词有两个来源：一是多智能体后端（已接入，见 [multi-agent-backend.md](multi-agent-backend.md)），每一轮在手机上排进同一个队列，并镜像给导演台；二是导演台（5174，见下文「导演台」）经「舞台通道」发送。店铺数据经 `shopFromRestaurant` 进入生成器；现在用的是大众点评的 66 家真实店铺，导入与字段见 [shop-data.md](shop-data.md)。语音（CosyVoice3）留给之后的流式多智能体系统。

## 分层

```

  generation/          店铺信息 → 店主：形象 → 口音 → 组件三步（每步先问 Jev，失败就用关键词规则），品牌店用品牌角色；distinct.ts 让同台店主互相区分

  jev/                 台词决策：组 state、出题、关键词基线、/api/jev 客户端

  feed/                舞台通道协议与 SSE 客户端

src/stores/cast.ts     店主生成队列、状态与浏览器缓存
src/stores/stage.ts    舞台通道连接、台词队列、去重与回报
src/composables/       useLinePlayback（逐句演出）、useStageDirector（台上 Actor 的统一时钟）
src/components/HostAvatar.vue  传入餐厅：生成中显示剪影和进度，生成好后显示形象
server/                index.ts（入口）、app.ts（一个端口挂全部接口和两个页面）、jev.ts（Jev 转发，key 只在服务端）、stageRelay.ts（舞台通道中继）、
                       status.ts（/api/status）、publicConfig.ts（/api/config：运行时下发高德 key）、network.ts（代理设置）
examples/              多智能体后端接入示例（Node / Python，零依赖）
director/              导演台（5174）：演播 · 资产 · 系统，见下文「导演台」
```

## 店主生成

- **何时生成：**
  - 需求确认进入滑卡后，按顺序预取接下来 3 张卡的店主；
  - 右滑邀请的店插队；
  - 同时最多生成 2 家。
  - 每家店 3 次 Jev 请求，每次约 0.3 s。
- **生成期间：** 卡片头像显示店铺主色的剪影，加上三步进度点。
- **场记板：** 所有受邀选手生成完才能合板，等待时显示「选手化妆中… n/N」。
- **缓存：** 结果存在浏览器（`tonight-cast-v1`），键是店铺资料的指纹加生成器版本；资料一变就重新生成。
- **输入：** 生成器只读 `ShopInfo`：店名、菜系、人均、招牌、卖点、店主、简介、logo 与主色。
  - 演示数据由 `shopFromRestaurant` 转换：去掉招牌菜名前的「招牌」，地址不参与生成。演示地址都在上海，否则每家店都会被判成上海口音。
  - 有 logo 时用 `generation/logo.ts` 的 `processLogo` 取主色，结果填进 `ShopInfo.logo` 和 `colors`。
- **品牌店（`generation/brands.ts`）：** 店名或店主命中品牌时，由品牌角色出镜，这时只有「组件」一步问 Jev。
  - **吉祥物（专门画的身体）：** 蜜雪冰城的雪王、茶百道的熊猫、霸王茶姬的茶姬、茶颜悦色的仕女、星巴克的塞壬。
  - **快餐连锁（人形模板加品牌行头）：**

    | 麦当劳 | 麦当劳叔叔 | 红色爆炸卷发、白脸红鼻子、红色笑嘴，黄色连体服配红色条纹袖、红色大鞋，手捧薯条 | 英式口音普通话 |
    | 老乡鸡 | 老乡 | 招牌上的草帽农夫：草帽、蓝布衫、绿围裙，怀里抱一只老母鸡 | 普通话 |
    | 赛百味 | 小麦 | 绿色遮阳帽檐、绿色 Polo 衫配黄领口，举一根长三明治 | 英式口音普通话 |
    | 德克士 | 德克 | 棕色牛仔帽、小胡子、红色 Polo 衫配黄领口，手举炸鸡腿 | 英式口音普通话 |

    | 食其家 | 阿食 | 橙色包头巾、橙色 Polo 衫，捧一碗牛丼 | 日式口音普通话 |

  - 肯德基上校、麦当劳叔叔、老乡鸡招牌上的草帽农夫来自品牌自己的形象；其余品牌没有官方角色，这里按品牌色和招牌食物设计。品牌标识归各品牌所有，仅作演示。
  - 同一品牌的分店一起上台时，第二家派店员出场，例如麦当劳是「麦麦小姐姐」「汉堡小哥」，肯德基是「炸鸡小哥」，见下一条。
- **同台的店主互相区分（`generation/distinct.ts`）：** 每家店主是单独生成的，同类店铺仍可能撞脸：Jev 几乎给每位厨师都戴白色厨师帽，一半人戴眼镜，同一品牌的两家分店会是同一个角色。所以按邀请顺序再过一遍台上阵容，只改前面的人已经造成混淆的地方：
  - 同一品牌第二家起改派店员，名字和形象都换；
  - 台上最多一顶白色厨师帽（高帽或小帽），最多两人戴眼镜；
  - 和前面某位太像时（性别、服装、帽子、发型、年龄、身高、衣服色相、配饰综合打分，满分 12，达到 7 分就算太像），依次换帽子、服装、发型、衣服颜色、眼镜、发色，直到不像为止；
  - 性别和年龄不改，因为店主名和后端的音色都跟着它们；
  - 结果在 `cast.contractOf` 里统一套用，所以舞台、后端拿到的名字和音色、导演台看到的都一样；同一阵容每次都一样。
- **胸牌用店铺头图：** 胸牌印的是店铺的封面照片（大众点评资料里的菜品图或用户实拍），裁成圆形，存成约 4–6 KB 的 JPEG 随店主缓存；照片读不出来时直接引用原图地址；店铺没有真实照片时（只有菜系示意图），胸牌印店名首字。
  - 胸牌放大到原来的约 1.6 倍，吉祥物也戴上了；
  - 舞台上人物很小，所以每位店主名牌下面再加一行：店铺头图的小圆图加店名（不带分店和菜名），一眼能看出谁代表哪家。
- **形象差异（`generation/variety.ts`）：** Jev 对同类店铺往往给出同一个首选，店主会长得很像。所以每个部件都在 Jev 认为可能的选项里抽取：
  - 适用部件：性别、年龄、体型、发型、服装、帽子；
  - 抽取范围和权重：概率不低于 5% 的选项都可能被抽到，权重取 √p；
  - 随机种子是店名，同一家店每次生成的样子不变；
  - 另外随机：发色按年龄取、肤色有 6 档；眼镜、小胡子、耳环按 Jev 给的可能性随机佩戴；店主名从更大的姓氏池和外文名池里取；
  - 真实店铺的主题色在所属菜系的色系内按店铺 id 取不同深浅。
  - 生成器版本因此升到 2，旧缓存会重新生成。传 `variety: false` 时与 agent-studio 的 Python 生成器逐字段一致（对拍测试就这样跑）。
  - 高厨师帽只配厨师服；其他服装抽到高帽时，改用 Jev 认为第二可能的帽子。
  - 生成器版本 3：快餐连锁改由品牌角色出镜、胸牌改用店铺头图，旧缓存会重新生成。

## 一句台词怎么演

1. 台词进入队列。舞台空闲时取出，同时做两件事：
   - 编排 `prepare`：说话人上前一步，看向被回应的人；其他人转头看他；
   - 请求 Jev。
2. **Jev 的决策：**
   - 问题：说话人的表情、笑点表情、手势、动作、视线、强度、气泡和立场，以及每位听众各一道反应题。
   - 回答到达：说话人先摆出表情和手势（`intent`）。
   - 最多等 1 秒：超时就先按人设默认开演，Jev 晚到时中途补上反应。
3. **开演：**
   - 打字机每 65 ms 出一个字，表演在同一时钟上展开：被回应的人在 22% 处反应，旁观者在 40% 处，笑点表情在 64% 处。
   - 置信度低于 0.12 的选择改用人设默认值，控制台会标「默认」。
4. **结束：** 留出阅读时间，然后全员放松，取下一句。
- **其他情况：**
  - 暂停：打字机和下一句都会停住。手机页面切到后台会自动暂停；在电脑上，切到导演台那个标签页也算后台。
  - 只有轮到某句上演时才会问 Jev。在这之前台词排着队，手机回报「排队中」并附上原因（例如不在辩论页、已暂停、开场动画中），导演台的卡片和检视抽屉会把原因显示出来。
  - 同时开着两个手机页面时，两个页面都会演同一句并各自回报，导演台看到的状态会互相覆盖。测试时只开一个。
  - 「清空舞台」：中断当前这句，丢弃排队的台词，全员复位。
- **顾客插话（长按说话）：**
  - 正在说话的店主一惊，这句话在控制台记为「被顾客打断」；
  - 顾客的话按原有规则更新筛选条件；
  - 同时作为一句台词上台，由 Jev 决定各位店主的反应，并回报给控制台。
- **点台上的人物（`StagePeek.vue`）：**
  - 被点的人当场有动作反馈，三套轮换：星星眼 + 挥手 + 小跳、大笑 + 欢呼 + 弹跳、眨眼 + 竖拇指 + 点头。约 1.2 秒后表情和手势回到这句台词编排里它本该有的样子；正在说话的人只换表情、跳一下，不打断手势。系统设了「减少动态效果」时只换表情。名牌也会弹一下，形象还在生成的店主同样有反馈。
  - 旁边弹出它代表的店：手机上从底部升起，舞台留在上方；宽屏（≥ 900px）是右侧抽屉，舞台让到左边。内容有封面、菜系 / 人均 / 距离、标签、营业时间、地址、店主的话、亮点、提醒；真实店铺接着显示大众点评资料（评分、推荐菜、团购、评价）。嘉宾显示品牌、招牌、人设和开场白；点 Orb 显示主持人说明和台上所有人，点名字可切换。
  - 面板开着时正在演的这句照常演完，下一句等面板关掉再开演，不用再按继续；导演台会看到「手机上在看店铺资料」。再点同一个人或按 Esc 关闭；开始长按说话时自动收起。

## 舞台通道

| 方向 | 消息 |
|---|---|
| 导演台/后端 → 页面 | `line`（id、speaker、text、replyTo、topic、evidenceIds，可选 interrupt / override / replaces）、`cast`（走台）、`drop`（撤回）、`clear` |
| 页面 → 导演台/后端 | `snapshot`（阶段、台上阵容与生成状态）、`line-state`（queued / deciding / speaking / done / dropped）、`decision`（Jev 的各项选择，带中文名、置信度和 detail）、`agent`（生成好的店主合同）、`user-line` |

- **speaker：** 餐厅 id、嘉宾 id、`host`（主持人 Orb）或 `user`（顾客）。
- **replyTo：** 填之前台词的 id，用来告诉 Jev 这句在回应谁。
- **line 的三个可选字段：**
  - `interrupt`：插话。正在说的那句停下（记为「被插话打断」），这句排到最前面马上上演。
  - `override`：手动指定的表演槽位（`expr`、`gesture`、`act`、`gaze`、`delivery`、`stance`、`bubble`、`listener_<id>`）。Jev 照问，`makePlan` 用手动值替换，决策里这些槽位标 `manual`。
  - `replaces`：重播或编辑。新 id 照常上演，演完后历史里那一句保留原 id、换上新内容；手机没听过原句时就记在原 id 下。这样之后 `replyTo` 原句的台词都还找得到。
- **走台 `cast`：** `{ id, act, who, guest? }`，和台词进同一个队列、按顺序执行，结果用同一个 id 的 `line-state` 报回（done 或 dropped，附「舞台已满」「本就在台上」之类的说明）。
  - `enter`：本场店主从候场回来，或嘉宾登台（第一次登台要带 `guest` 资料：名字、店、人设、默认表演、颜色、形象 look，logo 不超过 48 KB）；
  - `exit`：下场，去候场；`remove`：嘉宾离开舞台和候场；`reset`：阵容复位，只剩受邀的店主。
  - 台上最多 6 位。每场最多邀请 5 家，所以 5 家都在台上时只能再上 1 位嘉宾。
  - 嘉宾在 Jev 眼里和店主一样（`kind: owner`），会被问旁听反应；嘉宾的台词进历史时带 `guest` 标记、不算轮次。阵容存在 sessionStorage，手机刷新后还在。
- **`drop`：** 还在排队的台词直接撤回；正在演的那句当场停下，全员复位。
- **`decision.detail`：** Jev 读到的 state、问的题目 key、全部回答（概率保留 3 位小数）、计划里每个槽位的置信度、门控与手动标记，一句约 5–9 KB。导演台的检视抽屉靠它显示。
- **`agent`：** 手机生成好的每位店主（受邀的和滑卡时预取的都算）各发一条，含生成决策。中继按 id 只留最新一条，晚打开的导演台也能收到。
- **中继：** 单条消息不超过 64 KB；每个发送方的积压不超过 300 条、512 KB；重放按序号、照顾背压分批写，掉线很久的导演台重连也不会被断开。
- **去重与断线恢复：** 页面按消息 id 去重；刷新或断线后，从「之前没有未完成台词的最新一条」之后重放。插话、撤回让台词不按顺序结束，也不会漏演。
- **协议与校验：** 都在 `src/agents/feed/protocol.ts`，白名单校验，不认识的字段丢掉；形象的枚举抄了一份，测试保证它和 rig 一致。

## 运行

```sh
npm run dev         # 5173：手机页面（加 :lan 版本对局域网开放：npm run dev:lan）
npm run director    # 5174：导演台，/api 代理到 5173（DIRECTOR_TARGET 可改成别的服务）
```

构建后（`npm run build`）用 `npm start` 运行，一个端口（默认 3000）同时提供手机页面 `/`、导演台 `/director/` 和全部接口。交接包里已经带着构建产物，解压后运行 `start.sh` / `start.bat` 即可，见 [HANDOVER.md](../HANDOVER.md)。

脚本或后端可以直接发一句台词：

```bash
curl -s -X POST http://localhost:5173/api/stage/send -H 'Content-Type: application/json' \
  -d '{"from":"console","message":{"kind":"line","id":"b-1","speaker":"bashi","text":"来我屋头坐坐嘛！","topic":"开场白"}}'
```

`.env.local` 需要 `TYPESAFE_API_KEY`。TypeSafe 在部分地区直连会返回 451，这时再设置：

```
HTTPS_PROXY=http://127.0.0.1:<端口>
NO_PROXY=localhost,127.0.0.1,::1
```

## 导演台（5174）

继承 agent-studio 的控制台：同样的三页、布局和深色风格。舞台在手机上，所以导演台不画实时人物，只用各角色的 rig 画头像和资产。所有角色都在 `director/src/core/registry.ts` 的一个名册里：手机生成的本场店主、agent-studio 生成的品牌 agent（`director/src/data/studio-agents/`：雪王 · 蜜雪冰城、茶姬 · 霸王茶姬、塞壬 · 星巴克）、导演台新建的 agent、6 个人形模板、5 个品牌吉祥物、原片三人，加上主持人 Orb 和台下的「我」。

**演播**
- **舞台监视卡（原舞台的位置）：** 手机阶段、在线手机数、正在演的这句（按手机的打字节奏估算进度）、「决策 / 开口 / 时长」，以及台上座次（Orb、店主、嘉宾，标出说话人和正在反应的人）。
- **Dock：**
  - 依次是「我」、台上的店主和嘉宾、Orb、候场的人、生成中的，最后是「+」。
  - 卡片显示当前表情的头像、状态（发言中 / Jev 决策中 / 反应中 / 排队 #n / 走位 / 待命 / 候场 / 化妆中）和「表情 · 手势」。
  - 点卡片或按 Alt+1…9 选说话人；⋯ 菜单里有下场 / 登场、撤下嘉宾、在资产库查看、删除新建的 agent。
- **「+」：**
  - 新建店铺 agent：店铺信息（「键：值」或自由文本，解析移植自 agent-studio 的 `parse_shop`）+ logo；在导演台里跑和手机同一个生成器，生成面板逐步显示来源（Jev / 品牌 / 规则）、耗时和结果；生成好收进资产库，登台并说开场白。
  - 邀请嘉宾：资产库里的 agent，或者还没有 agent 的品牌吉祥物（先按品牌生成一个）。
- **输入区：** 说话人、插话开关、话题、引用依据（按标题和图片挑，取自应用自己的店铺数据；协议里只传 id）、同时回复多句（最多 6 句，Alt+↑ 追加，Esc 清空），回车发送。
- **对话流：**
  - 每句一张卡：引用、文字、Jev 的表情（置信度）、手势、动作、立场、每位听众的反应头像，以及状态行（排队中 → Jev 决策中 → 发言中 → 时长；已打断 / 未上演；基线；先开演）。
  - 卡上的 ↩ 回复、⟲ 重播；⋯ 里有编辑（改完重新决策并重演）、检视、删除（还没演完就从手机撤回）。
  - 走台单独一行。
- **检视抽屉：** 来源、模型、耗时、题数和流水线时间；说话人、语气、旁听、评分各项都列出置信度环、门控 / 手动标记、完整概率分布和前三名，并能手动改；改完台上空闲时自动重播。下面是请求与响应 JSON，题面用手机同一个 `buildLineQuestions` 重建。
- **会话 ▾：** 保存（存在浏览器）、导出 / 导入 JSON、清空、已保存的会话（载入、▶ 载入并播放、删除）、循环播放。
  - 「播放全部」先清空手机队列、把阵容复位到会话开头，再按顺序把每句台词和走台重发一遍；进度显示在原来的卡片上。
  - 导演台自己的对话流存在 sessionStorage，刷新后还在；关掉再开时空白页会提示「恢复上次会话」。
- **事件：** 中继、手机、每句台词、走台、Jev 决策和生成的每一步，最新的在上，最多 160 条。

**资产**
- 左栏：总览、通用模板、品牌形象、品牌 agent、本场店主、新建的 agent、原片角色。总览里可以导入 agent-studio 的 agent JSON（`agents/<id>.json`）。
- 每个角色先是它自己的一页：模板是部件（发型、服装、帽子、配饰、主题色逐个画出来），吉祥物是品牌设定（可以直接请上台），原片角色是人设和色板，agent 是档案（店铺、人设、口音、开场白、店铺原文和每一步生成决策）。
- 然后是通用六类：表情 20、手势 26、动作 10、口型 18、眼睛与手型 10、特效 8。卡片进入视口才渲染并循环播放；点开是实时 rig 的详情抽屉，可以暂停、0.5× 慢放、看参数、导出帧序列 PNG。
- 每个角色都能导出 JSON / CSV。

**系统**
- 架构图：导演台（和以后的多智能体后端）→ 舞台中继 → 手机里的台词队列 → Jev → 表演编排 → 台上每位，以及手机端、导演台两条生成管线。事件经过时节点亮起、连线流动。
- 服务状态：中继、手机、Jev、意图解析模型、高德、代理、语音（`GET /api/status`，只说配没配，不返回 key）。
- 名册：台上、候场和资产库里每位 agent 的类型、店铺、口音、形象和来源。
- Jev 与原片编排一致性：把原片 13 句对白交给 Jev 重新决定怎么演，和手工编排逐项比对（开口表情、手势、身体动作、旁听反应的 Top-1 / Top-3），可导出结果。演员、语言和 agent-studio 当时给 Jev 的完全一样。

**没有继承的：** LiveKit 房间与 WoZ 用户研究面板（这套架构的舞台通道就是中继）；配音和方言改写、音色页与试听（语音暂未接入，agent-studio agent 的声音设定只做展示）；原片的台词口型条、3D 模型、概念图和「原片对白」回放（素材不在这个仓库）；「我」的称呼与音色设置。

## 以后要接入的

- **多智能体系统：**
  - 推送：每个智能体的台词以 `line` 消息 POST 到 `/api/stage/send`，`from` 填 `console`；
  - 另一种方式：实现一个 `StageFeed`，交给 `useStageStore().connect()`；
  - 回报：订阅 `GET /api/stage/events?role=console` 就能收到页面的状态和 Jev 决策；
  - 页面代码不用改；
  - 可以从 `examples/stage-bridge.mjs`（Node）或 `examples/stage_bridge.py`（Python）改起，两者都已经处理好连接、断线重连和逐句节奏；消息约定见 [HANDOVER.md](../HANDOVER.md) 第 4 节。
- **换数据源：** 大众点评数据已接入（见 [shop-data.md](shop-data.md)）。再换别的数据源时，让它产出 `ShopInfo`，有 logo 时先经过 `processLogo`；生成器、缓存和舞台都不用改。
- **语音：**
  - 生成器里先不做「声音」一步，合同里 `voice` 为 null；
  - 接入流式语音后：
    - 一句台词的时长和口型从音频来，替代打字机节拍；
    - 编排已经以「开演时刻 + 预计时长」为参数。

## 测试

- 同台区分与品牌识别：`scripts/distinct.test.mjs`。用改动前真实阵容的 5 位店主（4 顶白帽、4 副眼镜）验证改完最多一顶白帽、最多两副眼镜、两两不像、性别年龄和名字不变；同一品牌的分店派出不同店员；数据集里的连锁能认出来，「KPRO肯律」这类不会误认。
- 生成对拍：`scripts/agents-generation.test.mjs`。用 agent-studio 的 Python 生成器一次性导出了 11 家店的金标准（`scripts/fixtures/generation-golden.json`），TS 版本逐字段相等。
- 决策对拍：`scripts/jev.test.mjs`。15 个用例的 state、问题和基线答案与 Python 版逐位一致。
- 其他：`agents-cast.test.mjs`、`agents-stage.test.mjs`、`stage-relay.test.mjs` 覆盖生成队列与缓存、演员表、决策回报、台词队列，以及中继和协议。
- 走台与嘉宾：`stage-cues.test.mjs` 覆盖协议新消息的合法与非法样例、形象枚举与 rig 一致、阵容规则（6 位上限、本就在台上、复位）。
- 导演台：`director.test.mjs` 覆盖店铺文本解析（对拍 agent-studio Python 版 `parse_shop` 导出的 `fixtures/parse-shop-golden.json`）、agent-studio 合同导入、重播 / 编辑落回原卡、多台手机的回报只进不退、一致性检查的演员和语言与 Jev 金标准一致。
- 服务与接入：`server.test.mjs` 覆盖一个端口同时提供手机页面和导演台、路径越界防护、运行时配置不泄露密钥；`examples.test.mjs` 由测试扮演手机，检查接入示例的开场顺序、逐句节奏和回应顾客。

## 已知边界

- 舞台通道只有一个全局频道，也没有鉴权：局域网里谁都能往舞台发台词。部署到公网之前，要加鉴权或者按会话分频道。
- 同时开着几台手机时，每台都会上演导演台发的同一句台词，各自回报；导演台的状态栏会提示「手机 ×n」。卡片状态只会前进，不会被慢的那台拉回去。手机自己的台词（后端的回合、Orb 的串场）镜像给导演台时带 `mirror: true`，别的手机不演。
- 新打开的手机只收打开之后的消息：嘉宾要等手机打开后再请上台。
- 导演台的会话、新建和导入的 agent 都存在这台电脑的浏览器里；要换电脑，先导出 JSON。
- 辩论页在标签页隐藏时会自动暂停，暂停期间收到的台词和走台都在排队。
- 片子里 `rong` / `pierre` 两个角色有专属加成（星星眼、飞吻、鞠躬）。生成的店主 id 不同，所以不享受。
- 顾客插话里的中文数字（如「一百以内」）由原有的本地规则解析，目前识别不了。
