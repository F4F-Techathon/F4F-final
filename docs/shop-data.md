# 真实店铺数据（大众点评）

应用默认使用从大众点评抓取的 66 家上海浦东张江店铺。原来的 9 家演示餐厅仍保留，用于单元测试和生成器的金标准；用 `VITE_DATASET=demo npm run dev` 可以切回演示数据。

## 导入

数据是一个文件夹，内含 6 个 CSV：

| 文件 | 内容 |
|---|---|
| 商户基础信息.csv | 店名、商圈、类别、地址、三项评分、人均、经纬度、电话、营业时间 |
| 推荐菜.csv | 菜名、推荐人数、描述、图片 |
| 到店套餐.csv | 套餐名、售价、原价、折扣、销量 |
| 代金券.csv | 代金券名、售价、面值、折扣、销量 |
| 最新评论.csv | 昵称、时间、星级、正文、点赞数、图片 |
| 差评.csv | 字段同上 |

更新数据时运行：

```bash
node scripts/import-dianping.mjs ~/Downloads/已爬数据
```

脚本生成两类文件：

- `src/data/dianping/shops.json`：打进应用包，约 340 KB，gzip 后约 120 KB。每家店包含：
  - 基本资料；
  - 推荐菜前 6 道、团购前 3 个、全部代金券；
  - 最有用的 3 条评价和 2 条差评；
  - 根据评价统计的场景信号；
  - 从菜名推断出的过敏原和食材。
- `public/data/dianping/<店铺 id>.json`：每家店一份完整资料，包括全部菜品、套餐和评价。打开店铺页时才加载。

导入时的处理：

- **CSV 只当文本解析。** 图片只保留大众点评、美团 CDN 上的 https 地址。
- **每张评价照片只留一份。** 抓取数据里每张照片都列了两次：先是原图，再是缩略图，两个文件名开头相同。导入时只保留原图。
- **评价人昵称只留首字**，例如「闻**」。
- **去掉大众点评的表情代码**，例如 `[米饭]`。
- **同名连锁店加街道区分**，例如「麦当劳（中科路）」。
- **跳过缺 id 或缺坐标的店铺**，也跳过其他文件里对不上店铺的行。

## 进入应用

由 `src/data/dianping.ts` 把店铺转换成 `Restaurant`，再由 `src/data/restaurants.ts` 按数据集选择。

### 图片

直接加载 CDN 地址，`<img>` 设置了 `referrerpolicy="no-referrer"`：

- **卡片和详情页头图：** 用推荐人数最多的那道菜的图片，没有菜图时用评价里的照片。4 家店两者都没有，改用本地的菜系示意图，并在图片说明里注明。
- **详情页：** 推荐菜图片和评价图片点开可以看大图。

### 坐标与定位

- **坐标：** 经纬度直接交给高德（GCJ-02，和高德同一坐标系），用在滑卡小地图、详情页地图、开场地图，以及距离计算和距离筛选里。
- **默认搜索中心：** 店铺范围的中心，显示为「上海 · 张江」。位置选择里的推荐区域也换成张江。
- **用户位置：** 「我附近」和「使用我的当前位置」仍走高德定位。离张江太远会筛不到店。
- **旧数据迁移：** 浏览器里存过演示数据的旧状态，会保留需求文字，但位置重置到张江，同时清掉旧的选店和讨论记录。

### 字段怎么来

| 字段 | 来源 |
|---|---|
| 菜系 | 列表里的类别原样保留；筛选时按名称归组匹配，例如「川菜」能匹配「川菜馆」，「日料」能匹配「日本料理」，「快餐」能匹配「西式快餐」。筛选标签按组显示，并去掉「美食」「商场」这类泛类别。 |
| 辣度 | 川、湘、渝、麻辣等算辣；评价里经常出现「辣」也算辣；完全不提辣的算不辣；其余记为未知。「不能吃辣」只保留确定不辣的店。 |
| 安静 | 评价里「安静 / 包间」与「吵 / 排队」的次数明显偏向一边时才下结论，否则未知。 |
| 场景 | 由菜系推出，再结合评价里提到家人、朋友、商务、一个人的次数，以及人均价格。 |
| 过敏原和食材 | 从全部菜名、菜品描述和套餐名推断。推断宁多勿少，例如「鱼香肉丝」也算含鱼。没有任何菜品资料的店记为未知，有过敏原要求时排除。这只是推断，页面会提示以商家确认为准。 |
| 店主 | 列表里没有店主名，由生成器起名（例如「刘叔」）；生成完成前显示「店主」。蜜雪冰城、星巴克、茶百道由品牌吉祥物出演。生成器拿到的是店名正名：去掉「·」之后的菜名后缀和括号里的分店名，所以店主说「我是甬悦柒鲜园林餐厅的王叔」；卡片上仍显示完整店名。 |
| 卖点 | 生成店主时用：氛围标签、4 分以上的口味评分，以及团购最低价。 |
| 依据 | 顺序和演示数据一致，页面按位置读取：`[0]` 商家资料，`[1]` 一条评价，`[2]` 用餐前需要确认（引用一条差评）。之后是推荐菜、其他评价、差评和团购。 |

### 店铺详情页

有真实数据的店铺显示以下内容：

- 真实照片头图和「大众点评」标记；
- 三项评分和人均；
- 商圈和电话；
- 推荐菜，横向滑动；
- 团购与代金券；
- 评价，分「最新评价 / 差评」两栏，每次加载 10 条，长文点开看全文；
- 高德地图和导航入口。

## 规模与限制

- **生成量：** 滑卡时会预取后面几张卡的店主，边划边生成，一家店调 3 次 Jev。66 家店全部划完，最多生成 66 位店主。
- **导演台补收上限：** 中继只为每位店主保留最近一条合同，总共最多 40 份、256 KB。晚打开的导演台只能补收到最近生成的 40 位左右；一直开着的导演台会实时收到全部。
- **包体：** 主包约 630 KB，gzip 后约 230 KB，其中约 340 KB 是打包进去的店铺数据，`vite build` 因此会提示单个文件超过 500 KB。以后店铺更多时，可以把 `shops.json` 改成启动后再加载。
